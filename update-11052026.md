## Konsep Baru: VotingResultCenter

Sebelumnya, histori hasil round hanya tersimpan di masing-masing `VotingRoom`.

Setelah update ini, admin room bisa mengirim hasil round yang sudah selesai ke kontrak pusat bernama `VotingResultCenter`.

Kontrak pusat ini berguna untuk:

- Mengumpulkan histori dari banyak room.
- Melihat room mana saja yang sudah pernah submit hasil.
- Melihat berapa kali suatu room submit hasil.
- Melihat hasil submit versi tertentu.
- Menyimpan `historyHash` sebagai fingerprint data histori.

## Cara Kerja Versioning

Versioning dihitung per room.

Contoh:

- `RoomA` submit hasil round 1.
  - Di pusat tersimpan sebagai version 1 untuk `RoomA`.
- `RoomA` submit hasil round 2.
  - Di pusat tersimpan sebagai version 2 untuk `RoomA`.
- `RoomB` submit hasil round 1.
  - Di pusat tersimpan sebagai version 1 untuk `RoomB`.

Jadi version tidak global untuk semua room, tetapi dihitung masing-masing room.

## Cara Kerja Hash Histori Round

`VotingRoom` sekarang punya fungsi:

```solidity
getRoundHistoryHash(uint256 round)
```

Fungsi ini menghasilkan `bytes32` hash dari data histori round, yaitu:

- address room
- round id
- admin
- total voter
- total golput
- start timestamp
- stop timestamp
- candidate ids
- candidate names
- vote counts

Hash ini dikirim ke `VotingResultCenter` saat admin memanggil:

```solidity
submitRoundHistory(uint256 round)
```

Expected result:

- Jika data histori lokal di room sama dengan data yang pernah dikirim ke pusat, hash-nya akan sama.
- Jika ada perbedaan data, hash akan berbeda.
- Hash bisa dipakai frontend atau backend untuk verifikasi integritas histori.

## Flow Baru dari Room ke Pusat

### 1. Deploy kontrak

Deploy urutan yang disarankan:

1. Deploy `SponsorVault`.
2. Deploy `MinimalForwarder`.
3. Deploy `VotingRoom` implementation terbaru.
4. Deploy `RoomFactory` dengan address implementation terbaru.
5. Deploy `VotingResultCenter` dengan parameter constructor:

```solidity
roomFactoryAddress
```

Catatan:

- `VotingResultCenter` akan memvalidasi bahwa caller submit adalah room resmi dari `RoomFactory`.
- Validasi dilakukan melalui `RoomFactory.isRoom(room)`.

### 2. Admin membuat room

Admin membuat room lewat:

```solidity
RoomFactory.createRoom("Pemilihan Ketua RT 2026")
```

Expected result:

- Room clone baru dibuat.
- Address room masuk ke `RoomFactory.allRooms`.
- `RoomFactory.isRoom(roomAddress) == true`.
- Admin room tercatat di `RoomFactory.roomOwner(roomAddress)`.

### 3. Admin mengatur result center di room

Setelah room dibuat, admin memanggil:

```solidity
VotingRoom.setResultCenter(votingResultCenterAddress)
```

Syarat:

- Caller adalah admin room.
- Room sudah initialized.
- Room sedang `Inactive`.
- Address result center tidak boleh zero address.

Expected result:

- `VotingRoom.resultCenter()` berisi address `VotingResultCenter`.
- Event `ResultCenterUpdated` dipancarkan.

### 4. Admin menyiapkan voter dan kandidat

Admin menambahkan voter:

```solidity
VotingRoom.addVoter(voterAddress)
```

atau batch:

```solidity
VotingRoom.addVoters(voterAddresses)
```

Update penting:

- Sekarang voter bisa ditambahkan saat room `Inactive` maupun `Active`.
- Jika voter ditambahkan saat round berjalan, voter tersebut langsung eligible untuk vote di round berjalan.

Admin menambahkan kandidat:

```solidity
VotingRoom.addCandidate(candidateId, candidateName)
```

atau batch:

```solidity
VotingRoom.addCandidates(candidateIds, candidateNames)
```

Catatan:

- Kandidat tetap hanya bisa diatur saat room `Inactive`.

Expected result:

- Voter masuk ke registry voter.
- Kandidat masuk ke registry kandidat.
- Voter duplikat akan revert `DuplicateVoter`.
- Kandidat duplikat akan revert `DuplicateCandidate`.

### 5. Admin memulai voting

Admin memanggil:

```solidity
VotingRoom.start()
```

Syarat:

- Room `Inactive`.
- `roundReadyToStart == true`.
- Minimal ada 1 voter.
- Minimal ada 1 kandidat.

Expected result:

- Room berubah menjadi `Active`.
- `activeRoundStartAt` diisi timestamp.
- Event `RoundStarted` dipancarkan.

### 6. Voter melakukan voting

Voter memanggil:

```solidity
VotingRoom.vote(candidateId)
```

Syarat:

- Room sedang `Active`.
- Caller adalah voter terdaftar.
- Caller belum vote di round tersebut.
- Candidate id valid.

Expected result:

- `roundVotes[currentRound][candidateId]` bertambah 1.
- `roundTotalVotes[currentRound]` bertambah 1.
- `lastVotedRound[voter]` menjadi current round.
- Event `VoteCast` dipancarkan.

### 7. Admin menghentikan voting

Admin memanggil:

```solidity
VotingRoom.stop()
```

Expected result:

- Room kembali ke `Inactive`.
- Histori round disimpan di `roundHistories[currentRound]`.
- `roundHistorySaved[currentRound] == true`.
- `roundReadyToStart == false`.
- Event `RoundStopped` dipancarkan.

### 8. Admin submit histori round ke pusat

Setelah `stop()`, admin memanggil:

```solidity
VotingRoom.submitRoundHistory(round)
```

Contoh:

```solidity
VotingRoom.submitRoundHistory(1)
```

Cara kerja:

1. `VotingRoom` mengecek `resultCenter` sudah diset.
2. `VotingRoom` mengecek histori round sudah tersimpan.
3. `VotingRoom` menghitung `historyHash`.
4. `VotingRoom` memanggil `VotingResultCenter.submitRoundResult(...)`.
5. `VotingResultCenter` mengecek bahwa caller adalah room resmi dari `RoomFactory`.
6. `VotingResultCenter` menyimpan data sebagai version baru untuk room tersebut.

Expected result:

- Jika submit pertama dari room tersebut, version yang dibuat adalah `1`.
- Jika sebelumnya room sudah pernah submit, version berikutnya bertambah 1.
- Event `RoundHistorySubmitted` dipancarkan dari `VotingRoom`.
- Event `RoundResultSubmitted` dipancarkan dari `VotingResultCenter`.

## Contoh Kasus 1: Room Submit Hasil Round Pertama

Data:

- Room: `0xRoomA`
- Admin: `0xAdminA`
- Round: `1`
- Total voter: `3`
- Kandidat:
  - `1 = Andi`
  - `2 = Budi`
- Hasil:
  - Andi: `2`
  - Budi: `1`
- Golput: `0`

Alur:

1. Admin membuat room.
2. Admin set result center.
3. Admin menambahkan 3 voter.
4. Admin menambahkan 2 kandidat.
5. Admin start voting.
6. 3 voter melakukan vote.
7. Admin stop voting.
8. Admin submit histori round 1 ke pusat.

Expected result di `VotingResultCenter`:

```text
getRoomCount() = 1
getRoomAt(0) = 0xRoomA
getRoomAdmin(0xRoomA) = 0xAdminA
getRoomVersionCount(0xRoomA) = 1
getLatestVersion(0xRoomA) = 1
```

`getRoomVersionSummary(0xRoomA, 1)` mengembalikan:

```text
roundId = 1
admin = 0xAdminA
totalVoter = 3
totalGolput = 0
startAt = timestamp start
stopAt = timestamp stop
historyHash = bytes32 hash histori
submittedAt = timestamp submit
```

`getRoomVersionCandidates(0xRoomA, 1)` mengembalikan:

```text
ids = [1, 2]
names = ["Andi", "Budi"]
voteCounts = [2, 1]
```

## Contoh Kasus 2: Room yang Sama Submit Round Kedua

Data:

- Room: `0xRoomA`
- Round baru: `2`
- Kandidat tetap:
  - `1 = Andi`
  - `2 = Budi`
- Hasil round 2:
  - Andi: `1`
  - Budi: `2`

Alur:

1. Setelah round 1 selesai, admin memanggil `restart()`.
2. Admin memanggil `start()`.
3. Voter melakukan vote untuk round 2.
4. Admin memanggil `stop()`.
5. Admin memanggil `submitRoundHistory(2)`.

Expected result:

```text
getRoomCount() = 1
getRoomVersionCount(0xRoomA) = 2
getLatestVersion(0xRoomA) = 2
```

`getRoomVersionSummary(0xRoomA, 1)` tetap berisi hasil round 1.

`getRoomVersionSummary(0xRoomA, 2)` berisi hasil round 2.

`getRoomVersionCandidates(0xRoomA, 2)` mengembalikan:

```text
ids = [1, 2]
names = ["Andi", "Budi"]
voteCounts = [1, 2]
```

## Contoh Kasus 3: Room Berbeda Submit ke Pusat

Data:

- Room A: `0xRoomA`
- Room B: `0xRoomB`

Alur:

1. `0xRoomA` submit histori round 1.
2. `0xRoomA` submit histori round 2.
3. `0xRoomB` submit histori round 1.

Expected result:

```text
getRoomCount() = 2
getRoomVersionCount(0xRoomA) = 2
getRoomVersionCount(0xRoomB) = 1
getLatestVersion(0xRoomA) = 2
getLatestVersion(0xRoomB) = 1
```

Artinya:

- Version dihitung per room.
- Version `1` milik `0xRoomA` berbeda dari version `1` milik `0xRoomB`.

## Contoh Kasus 4: Admin Menambahkan Voter Saat Voting Berjalan

Data awal:

- Room: `0xRoomA`
- Voter awal:
  - `0xVoter1`
  - `0xVoter2`
- Kandidat:
  - `1 = Andi`
  - `2 = Budi`

Alur:

1. Admin start voting.
2. `0xVoter1` melakukan vote.
3. Admin menambahkan voter baru:

```solidity
VotingRoom.addVoter(0xVoter3)
```

4. `0xVoter3` melakukan vote.
5. Admin stop voting.

Expected result:

- `0xVoter3` eligible untuk vote walau ditambahkan saat round berjalan.
- Jika total voter saat stop adalah 3, maka `totalVoter = 3`.
- Jika hanya `0xVoter1` dan `0xVoter3` yang vote, maka:

```text
roundTotalVotes = 2
totalGolput = 1
```

Catatan:

- Karena `totalVoter` dihitung saat `stop()`, voter yang ditambahkan di tengah round ikut dihitung sebagai total voter round tersebut.
- Ini cocok jika aturan bisnis memperbolehkan voter susulan.
- Jika aturan bisnis tidak memperbolehkan voter susulan untuk round berjalan, maka perlu logic tambahan seperti `voterActiveFromRound`.

## Fungsi Baru di VotingRoom

### `setResultCenter(address newCenter)`

Dipakai admin untuk menyimpan address kontrak pusat.

Syarat:

- Hanya admin room.
- Room harus `Inactive`.
- Address tidak boleh zero address.

Expected result:

- `resultCenter` berubah ke address baru.
- Event `ResultCenterUpdated` dipancarkan.

### `submitRoundHistory(uint256 round)`

Dipakai admin untuk mengirim histori round ke pusat.

Syarat:

- Hanya admin room.
- `resultCenter` sudah diset.
- Histori round sudah tersimpan.

Expected result:

- Histori round tersimpan di `VotingResultCenter`.
- Version baru dibuat.
- Return value adalah version yang baru dibuat.

### `getRoundHistoryHash(uint256 round)`

Dipakai untuk menghitung hash histori round lokal.

Syarat:

- Histori round sudah tersimpan.

Expected result:

- Mengembalikan `bytes32`.
- Hash sama dengan `historyHash` yang dikirim ke pusat.

## Fungsi Baru di VotingResultCenter

### `submitRoundResult(...)`

Dipanggil oleh `VotingRoom`, bukan langsung oleh admin.

Expected result:

- Menyimpan hasil round sebagai version baru.
- Menolak submit dari address yang bukan room resmi factory.

### `getRoomCount()`

Mengembalikan jumlah room yang sudah pernah submit histori.

### `getRooms()`

Mengembalikan semua address room yang sudah pernah submit histori.

### `getRoomAt(uint256 index)`

Mengembalikan room berdasarkan index.

### `getRoomAdmin(address room)`

Mengembalikan admin room yang tercatat saat submit pertama.

### `getRoomWithAdminAt(uint256 index)`

Mengembalikan address room dan admin berdasarkan index.

### `getRoomsWithAdmins()`

Mengembalikan semua room dan semua admin-nya dalam dua array.

Expected result:

```text
rooms = [0xRoomA, 0xRoomB]
admins = [0xAdminA, 0xAdminB]
```

### `getRoomVersionCount(address room)`

Mengembalikan jumlah version yang dimiliki room.

### `getLatestVersion(address room)`

Mengembalikan version terbaru untuk room.

### `getRoomVersionSummary(address room, uint256 version)`

Mengembalikan metadata hasil submit:

- round id
- admin
- total voter
- total golput
- start timestamp
- stop timestamp
- history hash
- submitted timestamp

### `getRoomVersionCandidates(address room, uint256 version)`

Mengembalikan detail kandidat dan jumlah vote:

- candidate ids
- candidate names
- vote counts

## Error / Revert Baru

### Di `VotingRoom`

`ResultCenterNotConfigured`

- Terjadi jika admin memanggil `submitRoundHistory()` sebelum `resultCenter` diset.

`RoundHistoryNotSaved(uint256 round)`

- Terjadi jika admin mencoba submit atau hash round yang belum dihentikan / belum disimpan.

### Di `VotingResultCenter`

`UnregisteredRoom(address room)`

- Terjadi jika address yang memanggil `submitRoundResult()` bukan room resmi dari `RoomFactory`.

`VersionNotFound(address room, uint256 version)`

- Terjadi jika membaca version yang belum ada.

`ArrayTooLarge(uint256 provided, uint256 maxAllowed)`

- Terjadi jika data kandidat yang dikirim lebih dari batas `MAX_BATCH_SIZE`.

`InvalidAmount`

- Terjadi jika panjang array `candidateIds`, `candidateNames`, dan `voteCounts` tidak sama.

## Catatan Tentang Relayer, Deposit, dan Private Besu

Update ini belum menghapus `SponsorVault`, `MinimalForwarder`, `maxCostPerVoteWei`, atau fungsi deposit.

Alasannya:

- Penghapusan alur relayer menyentuh banyak bagian sekaligus:
  - Solidity
  - ABI
  - relayer backend
  - frontend pre-check gasless
  - dokumentasi deployment
- Untuk private network Besu, relayer tidak wajib jika voter punya native coin untuk gas.
- Relayer masih bisa dipakai jika ingin UX gasless, tetapi reimbursement bisa disederhanakan atau dihilangkan.

Rekomendasi berikutnya:

1. Jika sistem final memakai direct vote di Besu:
   - Hapus kebutuhan `maxCostPerVoteWei`.
   - Hapus deposit room untuk reimbursement.
   - Hapus pre-check relayer di frontend.
   - Sederhanakan `SponsorVault` atau hilangkan dari flow utama.

2. Jika sistem masih ingin gasless:
   - Pertahankan `MinimalForwarder`.
   - Putuskan apakah relayer perlu reimbursement on-chain atau cukup dibiayai operator private network.

## Catatan Deployment Penting

Karena `RoomFactory` memakai immutable `votingRoomImplementation`, room lama tidak otomatis mendapat fungsi baru.

Untuk menggunakan update ini:

1. Deploy `VotingRoom` implementation baru.
2. Deploy `RoomFactory` baru yang menunjuk implementation baru.
3. Deploy `VotingResultCenter` dengan address factory baru.
4. Buat room baru dari factory baru.
5. Set `resultCenter` di room baru.
6. Setelah round selesai, panggil `submitRoundHistory(round)`.
